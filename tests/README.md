# Python-тесты

Из корня репозитория, с Python 3.14:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m ruff check .
```

`conftest.py` отключает загрузку `.env` и устанавливает искусственные настройки
до импорта приложения. Тесты не используют локальный токен, параметры запуска
или рабочую базу. Каждый тест получает отдельный `tmp_path` и `DB_PATH` внутри
него. Схема автоматически не создаётся: интеграционный тест сам вызывает
инициализацию БД, в том числе при проверке миграций.

Подключение SQLite к файлу вне каталога текущего теста останавливается до
открытия файла. Допускаются базы в памяти; URI-пути SQLite не используются
и отклоняются. Для проверки нескольких баз создавайте их в своём `tmp_path`.
Изолированные тесты с подменённой БД должны явно подменять все операции,
включая очистку кэша и освобождение ключа идемпотентности.

Тесты HTTP API восстанавливают состояние приложения, маршруты и подмены
зависимостей после каждого сценария. Нужные ресурсы, например искусственный бот,
задаются самим тестом. Ожидания фоновых задач согласуются событиями, а таймаут
ограничивает зависание; число вызовов не выводится из короткого реального ожидания.

Криптографические примеры используют искусственные ключи и заранее вычисленные
подписи: ожидаемое значение не строится проверяемой функцией. Проверка точки
входа подменяет запуск runtime, а проверка обработки ошибки развёртывания
исполняет только настройки Bash и искусственную неуспешную команду. Бот и деплой
не запускаются; без Bash соответствующий тест явно пропускается.

Браузерные сценарии и команды запуска описаны в [browser/README.md](browser/README.md).
