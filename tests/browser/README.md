# Браузерные проверки Mini App

Playwright проверяет настоящий `tma/index.html`, `app.js` и `styles.css` в Chromium.
Каждый тест запускает отдельный HTTP-сервер на случайном порту `127.0.0.1`.
Два окна одного теста используют общие искусственные данные. Telegram SDK
заменён локальной заглушкой; обращения браузера к любым другим адресам блокируются
и завершают тест ошибкой. Python, бот, SQLite, `.env` и внешние сервисы не запускаются.

## Запуск

Нужен уже установленный Node.js 24. В каталоге репозитория:

```powershell
npm ci
npx playwright install chromium
npm run test:browser
```

Если в Windows уже установлен Edge, его можно использовать без загрузки Chromium:

```powershell
$env:PLAYWRIGHT_CHANNEL = "msedge"
npm run test:browser
Remove-Item Env:PLAYWRIGHT_CHANNEL
```

`npm run test:browser:ui` открывает интерфейс запуска Playwright. Скриншоты и
трассировки сохраняются в `test-results/` при ошибках; HTML-отчёт CI — в
`playwright-report/`. Эти каталоги не предназначены для коммита.

## Что проверяется

- Создание, предпросмотр, редактирование и удаление через элементы интерфейса;
  HTML в тексте отображается буквально.
- Все шесть типов расписания и отправленные поля, последний день месяца (`0`),
  ежегодное редактирование 29 февраля, неизменяемость типа при редактировании.
- Погодные поля, ограничение числа населённых пунктов, повтор до выполнения,
  автоудаление и исключение несовместимых настроек.
- Двойное нажатие, блокировка формы до ответа, потерянный ответ после создания
  и повтор с тем же ключом идемпотентности.
- Некорректный успешный ответ, HTTP 500/503/422, обрыв сети, истёкшая сессия,
  таймаут и повтор запроса с сохранением введённых данных.
- Конфликты версий в двух окнах: сохранение, предпросмотр и удаление требуют
  явного повторного действия после обновления данных.
- Отмена/Escape/Tab в диалоге удаления, восстановление фокуса, ошибки настроек
  часового пояса, ширина экрана 320 пикселей.

Ожидание сетевого ответа в проверках блокировки управляется явно: ответ
освобождается после проверок состояния формы. Таймаут проверяется переводом
браузерных часов на 20 секунд, без реального ожидания.

## Локальный стенд для ручного воспроизведения

```powershell
npm run test:browser:serve
```

Открыть `http://127.0.0.1:4173/tma/`. Сервер читает текущие файлы `tma/`, поэтому
после правки достаточно обновить страницу. По умолчанию список пустой.

Управление искусственными данными доступно только у этого тестового сервера:

```powershell
# Создать тестовую карточку; остальные поля заполняются безопасными значениями.
$sample = @{ reminders = @(@{ id = 1; reminder_text = "Тестовое напоминание" }) }
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:4173/__test/reset `
  -ContentType "application/json" -Body ($sample | ConvertTo-Json -Depth 5)

# Однократно подменить ответ на создание HTML-страницей с кодом 200.
$fault = @{ method = "POST"; pathname = "/api/tma/reminders";
  rawBody = "<html>Service unavailable</html>"; contentType = "text/html" }
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:4173/__test/fault `
  -ContentType "application/json" -Body ($fault | ConvertTo-Json)

# Посмотреть искусственные данные и отправленные запросы.
Invoke-RestMethod http://127.0.0.1:4173/__test/state
```

Поддерживаются одноразовые ошибки `{status: 503}`, задержка `{delayMs: 5000}`,
обрыв `{disconnect: true}` и ответ `{rawBody: "...", contentType: "..."}`.
`commitThenDisconnect` сохраняет данные и обрывает соединение, но браузер может
прозрачно повторить запрос. Поэтому автоматический тест потери ответа использует
`route.fetch()` с последующим `route.abort()`: запрос доходит до стенда, а ответ
гарантированно не доходит до приложения.

## Границы проверки

Стенд моделирует HTTP-контракт, версии и идемпотентность для проверки интерфейса.
Он не дублирует планировщик, валидацию и авторизацию бэкенда. По умолчанию даты
получают фиксированный часовой сдвиг для `Asia/Yekaterinburg`, `Europe/Moscow`
или `UTC`; расчёты переходов часовых поясов, будущих запусков и исторических
якорей расписания здесь не выполняются. Для 29 февраля используется заранее
подготовленный ответ сервера, а проверка расписаний сравнивает отправленный
payload. Корректность алгоритмов остаётся предметом Python-тестов.

Эти проверки не подтверждают доставку сообщений Telegram, работу реального
WebView, подписанного `initData`, погоды или production-инфраструктуры.
